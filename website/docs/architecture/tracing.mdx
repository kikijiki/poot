# Tracing a Model

A model is an ordinary Rust function that takes a `Builder` and records a graph. The CPU oracle (`poot_eval::eval`) evaluates
that graph tensor by tensor, and the planner lowers it to GPU kernels. This follows JAX's functional-transformations
pattern [^jax].

## The Builder and Traced handles

`poot_graph_ir::Builder` records equations. A `Traced` value is a type-only handle (a `ValueId` plus the minting builder's
brand); its `TensorType` is read through `Builder::aval`. A handle from another builder is a typed `BuilderError`
(`ForeignHandle`). Every builder call and every `poot_graph_ir::ops` helper returns a `Result`.

| Input | Builder call |
| --- | --- |
| Weights and tables | `Builder::constant` |
| Per-step inputs | `Builder::slot` / `slot_named` |
| KV cache | `Builder::state_input` |

Helpers in `poot_graph_ir::ops` append primitive eqns; none is an opcode:

```rust
let h = ops::rmsnorm(b, x, attn_norm, eps)?;
let q = ops::linear(b, h, q_proj, q_bias)?;
let q = ops::rope(b, q, cos, sin, pos)?;
let o = ops::attention_masked(b, q, k, v, n_rep, scale, mask)?;
let ff = ops::swiglu(b, gate, up)?;
```

`Builder::finish(out)` closes the graph; `Outputs::new(out).with_state(&[(state_in, state_out)])` carries state or declares
validation witnesses. A finished `Graph` is always well formed, and a pass changes it only through a re-checked edit.

## From a family to a step

A model family lives in `poot-models` and implements `Model::trace_into(spec, builder)`, which builds one step. Callers use
`trace(spec, limits)`, which checks the step against the schema and token count first. A `StepSpec` names the program and
carried inputs; its `StepShape` gives:

- rows, new tokens per row and cache capacity;
- the KV layout (contiguous or paged);
- logits for the last token or every token;
- an optional hidden-state carry.

A dense decoder is a short call of the shared pair in `poot_models::components::standard`:

```rust
let step = Step::new(&b, shape)?;
let logits = standard_stack(&b, &step, &stack, &params, layers, |b, l, x| {
    standard_layer(
        b, x, &layers[l].norms, &layer_params,
        // the mixer
        |b, h| attention(b, &step, l, h, &layers[l].attn, &attn_params),
        // the feed-forward
        |b, input| gated_ffn(b, input.block, &layers[l].ffn),
    )
})?;
step.finish(b, logits)?
```

`standard_stack` embeds the tokens, runs one `layer_scope` per layer, then applies the final norm and head. `standard_layer` is
`x += mixer(norm(x)); x += ffn(norm(x))`. MoE, latent-attention and Mamba2 families pass a different feed-forward or mixer;
shared pieces are reused ([Models, Registry and the Driver](./driver.mdx)).

Prefill and decode are one body: positions are absolute typed slots, so prefill continues from a position and decode is the
same graph with one new token.

**Adding a model is writing a graph.** A family is a checkpoint config reader, a table from weight names to `(layer, role)`,
and a tracer over shared components when its layers are non-standard. It gets one row in the registry's `SHIPPED` slice. KV
layout, batching, paging, weight format and device limits are binding choices, transforms or planner legalization, so nothing
else changes.

## How the tracer records eqns

Each builder call allocates a `ValueId`, infers the output `TensorType` with `OpKind::infer` (no data touched), appends an
`Eqn { op, inputs, out }`, and returns a `Traced`. Handles carry no data, so model code cannot branch on activations. That keeps
the graph identical every token, which capture and replay need.

## Consts, slots, state, and values

Eqn inputs have four kinds (see [The Graph IR](./graph-ir#storage-classes)):

| Kind | Holds |
| --- | --- |
| **Const** (`Storage::Const`) | Weights, embeddings, RoPE tables, declared by name; the loader binds buffers that never move. |
| **Slot** (`Storage::Slot`) | `Slot::Token`, `Slot::Pos`, and for paged decode `Slot::SlotMap` / `Slot::WriteMap` (word ranges checked at bind), rewritten in place each step. |
| **State** (`Storage::State`) | The KV cache; each `state_in` pairs with a `state_out` the executor overwrites. |
| **Device** (`Storage::Device`) | Every activation, at stable addresses fixed at plan time. |

The attention mask is built in-graph from `Slot::Pos`; no slot carries it.

A 24-layer dense decode step traces to a flat graph of roughly a thousand primitive eqns (count with
`poot_graph_ir::analysis::dispatch_count`). Shapes are static, and the trace takes milliseconds once at load.

## GQA and MQA: no special opcode

For GQA [^gqa] and MQA [^mqa], `ops::repeat_kv` expands K and V to Q's head count before the score matmul:

```rust
// k: [1, H_kv, cap, D]  ->  [1, H_kv * n_rep, cap, D]
let r = b.reshape(k, vec![bsz, h_kv, 1, seq, d])?;
let r = b.broadcast(r, vec![bsz, h_kv, n_rep, seq, d])?;
b.reshape(r, vec![bsz, h_kv * n_rep, seq, d])
```

When the flash rewrite fires, the fused op takes `n_rep` and reads the shared K/V rows directly (`kv_head = q_head / n_rep`).

## SwiGLU and GeLU FFN

SwiGLU [^swiglu] is `ffn(x) = (SiLU(gate_proj(x)) * up_proj(x)) @ down_proj`. `ops::swiglu` is `silu(gate) * up` between the
`MatMul`s, with `silu(x) = x / (1 + exp(-x))` built from `Neg`, `Exp`, `Add` and `Div`. GeLU [^gelu] variants swap in another
composition: `geglu` uses the tanh approximation over `Exp` and `Div`; encoder feed-forwards use the exact form on `Erf`. There
is no activation unary or FFN opcode.

## Checkpoint loading

`poot-load` reads safetensors directories and GGUF files into a weight store; the family's weight map binds tensors to named
consts.

- **Quantized formats** bind packed constants that stay packed. Dense projections decode in the consuming contraction; a packed
  expert stack is read by one indexed packed contraction.
- **Fused QKV** is split and transposed layouts corrected at load.
- **Dense BF16/F16** load as stored words, with one loader and no widened f32 copy. The graph casts norm scales, biases and
  embeddings to f32 (a gather casts only gathered rows); contractions read weights as stored.
- A stored dtype the graph cannot read is a typed error at bind.

## Mixture-of-experts routing

MoE layers (`ops::moe`, `moe_sparse`, `moe_grouped`) score experts, pick the top-k ids with `ArgTopK`, and contract each row
against its own expert with `IndexedMatMul`. Expert ids are runtime values computed in-graph each token; the structure is fixed.

- **Prefill** groups `(token, slot)` rows by expert: `ExpertGroup` returns the stable sort and its inverse, rows are gathered
  into expert order, contracted, then gathered back. A tile then shares each expert's weight tile across rows.
- **Decode** has too few rows to gain, so it contracts directly.
- **Weights:** dense expert tables are read in place. A packed stack becomes one indexed packed contraction over the stored
  blocks (one buffer per source role, experts padded to whole words); only selected experts' blocks are decoded.
