# The Driver

The `Driver` turns a [`ModelHandle`](./registry.mdx) and an executor into generation. It knows no family, and it never branches on a backend.

## Lifecycle

`Driver::new(handle, executor, options)` binds a handle to one executor. The options fix the prefill and decode compile options, the KV capacity, the prefill chunk size and the bound on what the driver may retain.

A new driver is `Driver<Unprepared>`. `prepare` takes it by value and returns the `Driver<Serving>`, so `open`, `step`, `commit` and `release` do not exist before it. A refused `prepare` hands the unprepared driver back with the typed error.

- **One executable.** The handle's weights load into the executor once. Each specialization is an entry on it, keyed by `(program, StepShape, Head, carried inputs)`.
- **No re-specializing.** Token ids, positions, seeds and sampler parameters are bound inputs. Capacity is part of the shape.
- **One compile path.** `Model::trace` builds the graph, the sampling suffix is appended, and the shared compiler for the executor's target compiles it.
- **Fixed set.** `prepare` warms every admitted entry, so a serving step compiles nothing. An entry is never replaced, and one over the entry-count or retained-byte limit is a typed refusal.

## Sampling

Every sampling rule runs on the device, as a suffix of the decode graph (`Head::Sample`): draws, penalties and bias, the guided-decoding mask and logprobs. [Serving design](./serving-design.mdx) lists them. The host reads back a token id and a non-finite flag, plus the logprob record when asked, never the logits.

A step runs the narrowest prepared head that serves all its rows; a request none serves is a typed refusal. `Head::Logits` is for callers that ask for full logits. With no guided row, `RowWork::Chain` chains several decode steps on the device, and the host waits once.

## Serving surface

The loop is `open`, `step`, `commit`, `release` over sequences and rows.

- `generate` drives it for one row with a sink for tokens.
- `SeqRequest` is one admission value: prompt, adapter and the `RequestInputs` the model declares.
- `encode` runs an `encode` step over rows.

A sequence that carries request inputs bypasses the prefix cache, which keys on tokens alone. It is refused at admission under an adapter not prepared for that input, and a draft policy that cannot read the inputs does not speculate on it.

## What composes

Features of the driver and of a request (draft policy, placement, recurrent state, adapter, beam search, request inputs, resuming a sequence, the paged pool) are checked against one compatibility table. A refused pair is one typed `Incompatible` error naming both features and the reason. No other per-pair check exists.

The CPU oracle is a test-side reference, not an executor the driver can choose.
