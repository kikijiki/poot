# Execution

Compile once (trace, optimize, plan, capture), then replay per token. This page covers what is captured, how each backend
replays it, and how faults surface.

## Why capture

A small-batch decode step is memory-bound, and each driver call costs microseconds. With dozens of dispatches per token the
CPU sets the pace; native replay removes those calls.

<ExecutionTimeline />

## A constant-shape decode graph

Replay needs identical dispatches every token, so poot uses **fixed-capacity KV with masking**:

- K and V are `Storage::State` buffers preallocated to `cap` positions per layer.
- Each step writes the new K/V at `pos` (`DynamicUpdateSlice`, or `ScatterUpdate` through `Slot::WriteMap` for paged KV).
- Attention sweeps all `[cap]` positions; a mask built in-graph from `Slot::Pos` hides those after `pos`.

Grids and buffer addresses stay constant, so one capture serves every position up to `cap`.

## Slot buffers

Per-step inputs (`Slot::Token`, `Slot::Pos`, and `Slot::SlotMap` / `Slot::WriteMap` for paged KV) live in device buffers at
stable addresses. Recorded kernels point at them, and the host rewrites their contents before each replay. A scalar that depends
on a slot is bound to the slot buffer, never baked into the capture.

## Per backend

| Backend | Capture (once) | Per token |
| --- | --- | --- |
| PTX | `cuStreamBeginCapture`, launch every plan, instantiate | Write slots, `cuGraphLaunch`, copy logits, sync. |
| ROCm | Record the AQL packets of every plan. | Write slots, resubmit packets, read back. |
| Vulkan | Record command buffers (pipeline bind, descriptor bind, dispatch or copy, full barrier). | Write slots, resubmit verbatim with a fence wait each, raise the staged kernel fault at `synchronize`. |
| wgpu | Build pipelines and bind groups, cache the dispatch list. | Write slots, encode from cache, submit, map. |

- **Vulkan:** descriptor sets are baked at record time. A device with a watchdog budget gets several command buffers per replay,
  cut by the planner's per-dispatch work weight.
- **wgpu:** the re-encode still encodes per token; a token step is not allocation-free.

## The executor contract

`poot-executor` holds the backend-neutral contract: one generic `Engine<D>` over a per-backend `Device` trait implements an
object-safe `Executor`, so the driver never branches on a backend.

| Item | Members |
| --- | --- |
| `Executor` methods | `target_set`, `load_weights`, `add_entry`, `step`, `reset_state`, `remove_entry`, `stats`, `unload` |
| Devices | `WgpuDevice`, `RocmDevice`, `PtxDevice`, `VulkanDevice`; experimental `XdnaDevice`, `VpuDevice` ([NPU Offload](./npu.mdx)) |

`load_weights` binds each weight a graph names by its typed role through a weight map. A const the map does not name stays
unbound, even if a store key spells its name.

## The driver

The `poot-llm` driver ([Models, Registry and the Driver](./driver.mdx)) uses this contract on every backend.

1. `Driver::new` loads the weights once, as one executable.
2. Each step shape becomes an entry on it, traced by the family and compiled for the target. Entries are keyed by program,
   shape, sampling suffix and carried inputs, so a token, position or sampler value never makes a new one.
3. `Driver::encode` runs encoder, hidden-state and vision-tower steps; `Driver::generate_with_inputs` binds prompt-supplied
   inputs (such as image rows) by value.

Sampling runs on-device and is appended to the decode graph. The host reads back only the token id, a non-finite flag and any
top-n logprobs. `poot-serve` runs the driver in one scheduling loop ([Continuous batching](../serve/continuous-batching.md)).

## Failure handling

A device fault is a typed error on every backend and never aborts the process.

| Backend | Fault source |
| --- | --- |
| ROCm | HSA queue error callback and system event handler |
| PTX | Sticky CUDA error |
| wgpu | Device-lost callback |
| Vulkan | Failed submission or fence wait; the device is poisoned |

- The call that sees a fault returns a device-lost error and poisons the context; later calls are refused without touching the
  device. If a device cannot clean up after a failed step, the engine is poisoned too.
- Waits on ROCm, wgpu and raw Vulkan time out (600 s by default) with a typed error and poison the context.
- ROCm and PTX execute a device trap for a failed kernel check. SPIR-V has none, so Vulkan and wgpu set a fault bit and
  continue under robust buffer access; `synchronize` then raises a typed fault naming the kernel and trap code.
- A step that fails after replay needs `reset_state`; `step` refuses until it runs.

## Verification

`poot_eval::eval(&graph, &inputs, EvalOptions)` is the CPU reference. Tests and device checks call it; generation never does.
Three tiers (requirements, not a claim of complete coverage):

1. **Bit-exact where it can be:** graph transforms, integer and packed-byte work, movement ops, routing ties, capture versus
   eager on one device.
2. **Stated tolerance for floats:** every output and carried-state element, within a tolerance derived from reassociation.
3. **Tokens on real checkpoints:** greedy tokens match an independent reference (Hugging Face transformers, llama.cpp). A flip
   is allowed only inside the reference's top-two margin. Instruct models use their chat template.

NaN or infinity where the oracle is finite fails at any tolerance. A test skipped for a missing device is reported as a skip.
