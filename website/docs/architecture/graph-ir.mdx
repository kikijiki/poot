# The Graph IR

The graph IR is poot's central abstraction: a flat, typed, topologically ordered list of primitive tensor equations in SSA form. The tracer, the fusion pass, the backends and the executor all produce or consume it.

## Why a fine-grained primitive IR

General kernel fusion needs an IR finer-grained than the kernels it produces, as in XLA [^xla], TVM [^tvm] and JAX [^jax]. Attention, RMSNorm, RoPE and SwiGLU are therefore compositions of matmul, reduce, elementwise and broadcast, not opcodes.

Flash attention [^flash1] is not a primitive either. A model composes attention with `ops::attention_masked(...)`, and `compile` rewrites supported subgraphs to one fused dispatch, depending on shape, target and fusion policy.

## Graph structure

A `Graph` is private; it is read through accessors and changed only through a checked edit. Its main tables:

- `values`: shape, dtype and storage class per id.
- `inputs`: all binders. `consts` and `slots` are subsets.
- `eqns`: topologically ordered SSA equations. Each has an `op`, `inputs` (a `ValueId` or a literal) and one `out`.
- `outputs`: the result, witnesses, exports and next-state values (`OutputKind`).

`Builder::finish` and `GraphEdit::commit` check the whole graph. A pass opens `graph.edit()`, changes the draft and commits it; a rewrite that loses a witness, an export or a carried-state pair, or changes the result's type, is refused with a typed error.

`ValueId` is a `u32` newtype. A value is defined by the one `Eqn` whose `out` is its id, so there are no separate def-use chains.

## Storage classes

| Class | What it is |
| --- | --- |
| `Device` | An ordinary intermediate tensor: attention scores, MLP outputs, the residual stream |
| `Const` | A weight or table, identified by its `WeightRef`, never by a name; weight caches never reuse different bytes |
| `Slot(Slot)` | A per-step input in a stable device buffer the host rewrites in place |
| `State` | A buffer carried across decode steps: the KV cache |
| `Computed` | A compiler-defined constant, such as a folded `Iota` |

**Slots.** `Token` and `Pos` carry the step's ids and absolute positions. `SlotMap` and `WriteMap` carry paged KV reads and writes, each declaring the range of the words it holds, which the bind checks. Other roles (the adapter index, the expert pool, the sampler inputs) are defined by the pass or feature that declares them. The attention mask is not a slot: it is computed in-graph from `Pos`.

**State.** A state buffer is pre-allocated to `cap` per layer. `Graph::state()` pairs each `state_in` with a `state_out` of the same type. The executor overwrites the buffer with `state_out` (the JAX `donate_argnums` contract), which also orders the KV read before the KV write.

## Primitive operations

Tracers emit the primitives: elementwise, reduce, movement, matmul, gather/scatter and quantization. The optimizer introduces the composites (`Fused`, `FusedRow`, `ContractionEpilogue`, `Attention`, `Rope`, `BlockTopK`, `SelectedAttention`, the packed and dense contraction ops). Each has the semantics of the chain it replaces, and a tracer cannot emit them.

`Scan` is the exception. It states a recurrence, and tracers emit it with a primitive definition the CPU oracle evaluates.

A sparse-attention indexer writes its selection as primitive chains. The selection pass of `compile` forms `BlockTopK` and `SelectedAttention` from them, and a device that cannot plan them refuses the composite.

No op records a kernel choice; which kernel runs an eqn is a property of its plan.

## What composites decompose to

The tracer records a higher-level op as primitives. RMSNorm [^rmsnorm] is seven eqns, fused into one reduction kernel:

```text
sq  = Mul(x, x)
ss  = Reduce(Sum, sq, axis=-1, keepdim)
ms  = Mul(ss, 1/D)
mse = Add(ms, eps)
den = Unary(Sqrt, mse)
xn  = Div(x, den)
out = Mul(xn, weight)
```

RoPE [^rope] is the rotate-half chain (`ops::rope_partial`), with `cos` and `sin` gathered from constant tables:

```text
x1, x2 = Slice(x, 0..D/2), Slice(x, D/2..D)
out = Concat([Sub(Mul(x1,cos), Mul(x2,sin)),
              Add(Mul(x1,sin), Mul(x2,cos))], axis=-1)
```

`compile` replaces it with one `Rope { rot }` eqn over `[x, cos, sin]`, one synthesized kernel instead of about 6-8 dispatches.

Softmax is the two-pass safe pattern: a Max reduce, subtract, exp, a Sum reduce, divide. Flash attention uses the streaming "online" variant instead; see [Attention](./attention#the-streaming-schedule).

## Host-side shape inference

Every `OpKind` implements `infer(input_types) -> output_type`, run on the host at trace time. All shapes are static, so:

- the executor knows every buffer size before the first dispatch and allocates at stable addresses, which recorded replay (CUDA graphs, HSA packets, Vulkan command buffers) requires;
- the planner picks kernel specializations (GEMV vs GEMM, the attention schedule) at compile time.

Per-step inputs (`Slot::Token`, `Slot::Pos`) are small buffers the host writes each token. Output shapes never depend on slot values, because the KV capacity is fixed, so a captured graph stays valid at every position.

## Quantization

`PackedDequant` is the one packed-weight primitive. Its `poot-quant::PackedWeight` descriptor names the `WeightFormat`, shape and source roles. The compiler recognizes dense projections as `PackedContraction` and embedding lookups as `PackedRowGather`, and generated kernels decode only the weight values they consume.

GPTQ, AWQ, supported GGUF quants and the registered FP8/E2M1 layouts use this lowering. A packed MoE expert stack is rewritten when its weights are bound into one indexed packed contraction that decodes only the selected experts' blocks.
