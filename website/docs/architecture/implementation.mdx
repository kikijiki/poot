# Crates and implementation details

Which crate owns which layer, and the few constraints that span several pages.

## Crate map

| Layer | Crates | Role |
| --- | --- | --- |
| Foundations | `poot-tensor`, `poot-target` | `DType`, host tensors; `Backend`, `TargetId`, `DeviceCaps` |
| Graph IR | `poot-graph-ir` | Graph, `Builder`, `ops`, `transform` passes |
| CPU oracle | `poot-eval` | Test-side reference evaluator |
| Planning | `poot-graph-plan` | `compile`: passes, plans, storage, slots; typed refusals |
| Kernel import | `poot-kernel-attr`, `poot-kernel-intrinsics`, `pootc` | `#[kernel]`, intrinsics, the rustc importer |
| Kernel IR, synth | `poot-kernel-ir`, `poot-kernelgen` | Kernel body IR; synthesized bodies |
| Codegen | `poot-codegen` | Kernel IR to LLVM IR to SPIR-V, PTX, AMDGCN or AIE: the `CompiledKernel` |
| Runtimes | `poot-{wgpu,rocm,ptx,vulkan}-runtime`, `poot-runtime-common` | Devices, buffers, transfers |
| Executor | `poot-executor` | `Engine<D: Device>`: the one contract every backend implements |
| Devices | `poot-{wgpu,rocm,ptx,vulkan}-device` | Load, bind, capture, replay, read back |
| NPU | `poot-npu`, `poot-npu-artifacts`, `poot-l0-runtime` | Experimental devices ([NPU Offload](./npu.mdx)) |
| Models | `poot-models` | `Model`, the registry, family tracers |
| Loading | `poot-load`, `poot-quant`, `poot-weights` | Safetensors and GGUF readers, packed descriptors, weight roles |
| Text | `poot-text` | Tokenizer, chat templates, guided decoding; no model or device |
| Generation | `poot-llm` | `ModelHandle` and the driver |
| Serving | `poot-serve` | OpenAI-compatible HTTP server |
| Tooling | `poot-orchestrator`, `poot-profile`, `poot-test-util` | Pod runs, profiling, test helpers |

## Cross-cutting notes

- **The NPUs sit outside the foundation crates.** `poot-npu-artifacts` holds the link recipe, the linked artifact and the Intel graph artifact, and `poot-npu` links and loads them. `poot-graph-plan` and the engine reach it through two capability objects they define and `poot-npu` implements (the lowering a compile is handed, and the region loader a `Device` owns). See [NPU Offload](./npu).
- **The CPU oracle is test-side.** `poot-eval` is what tests compare against; generation never calls it. See [Execution](./execution#verification).
- **Attention has its own value width, split keys and paged keys.** The fused op types a value head narrower than the key head, a key split into per-head and shared parts (MLA), and keys and values read in place from paged pools through a slot map. See [Attention](./attention#implementation-details).
- **ROCm AQL publication.** Replay writes AQL packets to a host-coherent ring, then rings the doorbell. A discrete-GPU device-memory ring needs an explicit store fence first; integrated APUs refuse that constructor.
- **Synthetic checkpoints.** Some families are verified only on bounded synthetic checkpoints against the CPU oracle, which is not a real-checkpoint claim. The [Performance page](../performance/index.mdx) lists what was measured.
