# NPU Offload

:::note[Compiles, does not execute]
The NPU runtime and executor have been removed. No `--backend` or library execution path reaches a
laptop NPU today, but NPU support (Intel and AMD) remains a poot objective. The compiler side exists as a
typed target, a typed shape and argument ABI and a linked-artifact format for AMD XDNA2, and a sequential
one-core schedule the planner can choose. Nothing runs on hardware: no executor loads these artifacts, and
no Peano/IRON positive compile or device parity has been recorded. It does not provide usable NPU support.
:::

Before removal, poot had an experimental, opt-in NPU library path (not a serving option): Intel
prefill through OpenVINO IR and Level Zero, and AMD XDNA2 prefill through a Peano/IRON-built xclbin
dispatched over XRT. Those runtime paths are gone. The typed compiler artifact and ABI now exist; a
device implementation that loads and runs them does not. It will re-enter on the single pipeline.
