# Kernels from Rust

Imported GPU kernels are Rust functions, type-checked and borrow-checked by rustc. One source produces SPIR-V for wgpu and raw Vulkan, PTX for NVIDIA, and an AMDGCN code object for ROCm. Other kernels are synthesized; see [Fusion](./fusion).

## A kernel looks like this

```rust
#[kernel]
pub fn elementwise_add(a: &[f32], b: &[f32], out: &mut [f32]) {
    let i = thread_index_x();
    if i < out.len() {
        out[i] = a[i] + b[i];
    }
}
```

The ABI is slices: inputs as `&[T]`, outputs as `&mut [T]`. The attribute renames the function into the reserved `__poot_kernel_<name>` namespace for pootc. A normal host build gets a typed launch wrapper instead of the body, so kernel bodies need not be host-compatible.

**pootc** is a thin rustc driver. It calls rustc normally and hooks `after_analysis` to visit every `#[kernel]` fn's MIR body through Stable MIR [^stableMir], the stable, versioned interface to rustc's Mid-level IR.

**Kernel IR** (`poot-kernel-ir`) is a small CFG-based IR of basic blocks, statements (`Assign`, `WorkgroupLocalWrite`, `VectorStore`, `Wmma*`) and terminators (`Goto`, `SwitchInt`, `ThreadIndexCall`, `Barrier`, `Return`, `Trap`). The importer only needs to know it, and the backends only need to consume it.

A kernel binary is bound to a compute `Plan` produced by `plan_eqn`, which `compile` runs last. The planner chooses an imported or a synthesized body by region description and target, never by model; [Fusion and Planning](./fusion) owns which ops take which.

Imported sources live under `crates/pootc/kernels/<family>/`: `packed`, `sampling`, `state`, and `probe` (test fixtures). Matmul and elementwise kernels are never imported; they are generated.

## Accepted Rust subset

This section is the one statement of what a kernel may contain, derived from `crates/pootc/src/import.rs` and `poot_kernel_intrinsics`. Anything else is a named `unsupported in kernel: ...` diagnostic from pootc, never a silent miscompile.

| | Accepted | Rejected |
| --- | --- | --- |
| Types | `bool`, `usize`, `i32`, `u32`, `f32`, `f64`, `f16`, unit, references and raw pointers to those, slices | Structs, tuples, arrays, enums, closures, trait objects, `Vec`, `Box`, `String` |
| Expressions | Arithmetic, bit ops and shifts, comparisons, unary `-` and `!`, numeric `as`, slice indexing, `len()`, `if / else` | |
| Loops | `while`, `for k in a..b`, `a..=b`, `for x in slice` | `.rev()`, `.step_by()` |
| Methods | Float `sqrt abs floor ceil trunc round exp ln sin cos`; `max` and `min`; `f32::from_bits(u32)` | Any other function: no inlined helpers, `unwrap`, `expect`, recursion or I/O |
| Arrays | Workgroup memory (below) | Private arrays with dynamic indices |

The importer matches a `core` or `std` method by its resolved path, so a kernel-authored helper of the same name is an ordinary call and is rejected.

### Intrinsics

The only other calls a kernel may make are `poot_kernel_intrinsics` functions, recognized by their resolved declaration:

- `thread_index_{x,y,z}()`, `local_index_{x,y,z}()`, `group_index_{x,y,z}()`: the global dispatch index, the lane within its workgroup, the workgroup index.
- `workgroup_barrier()`: earlier workgroup-local writes are visible to every lane after it.
- `wg_write::<T>(array, i, v)` and `wg_read::<T>(array, i)`: LDS access. `array` is a literal id of a declared array.
- `atomic_add(buffer, i, v)`: atomic `u32` add on a slice parameter, returning the old value.
- `no_contract_add(a, b)`: an add no backend may fuse with a producing multiply into an FMA.

### Declared launch

`#[kernel(workgroup(x, y, z), lds(T, len), ...)]` states the launch, and the importer reads exactly that. `workgroup` is the lane count per axis (missing axes are 1). Each `lds(T, len)` declares the next workgroup-local array: `len` elements of `f32`, `u32` or `i32`.

A kernel that reads a lane or workgroup index, calls the barrier or touches an LDS array must declare its workgroup. Without one it runs at 64 lanes along X.

### Failed checks

A MIR `Assert` (a bounds, overflow, divide or shift check) lowers to a branch that traps, and `Unreachable` lowers to a trap. A check a dominating guard provably repeats is dropped.

- **ROCm, PTX:** a device trap instruction.
- **wgpu, raw Vulkan:** SPIR-V has no trap. `poot-codegen` sets a per-thread bit for the failed site in the dispatch's error word (up to 32 sites per kernel; more share the last bit), and the thread carries on under robust buffer access. The executor discards the dispatch and raises a typed fault at its next sync point.
- **XDNA2 NPU (AIE):** `poot-codegen` refuses a body that contains a trap, with a typed error.

## LDS arrays and barriers

Workgroup-local memory is declared in the attribute and indexed by a literal array id:

```rust
#[kernel(workgroup(64), lds(f32, 64))]
pub fn wg_reduce(a: &[f32], out: &mut [f32]) {
    let lane = local_index_x();
    wg_write::<f32>(0, lane, a[lane]);
    workgroup_barrier();
    if lane == 0 {
        let mut acc = 0.0f32;
        for j in 0..64 { acc = acc + wg_read::<f32>(0, j); }
        out[0] = acc;
    }
}
```

Use LDS instead of a local `[f32; N]` for SPIR-V: private arrays with dynamic indices crash some driver stacks (RADV). The generated attention kernel keeps its running output in LDS for this reason. A structurization pass turns the unstructured CFG into loops and if/else before SPIR-V emit.

## Committed assets

Each imported kernel has a committed `.kir.json` under its consuming crate's `assets/`, generated from `crates/pootc/kernels/<family>/`. This keeps GPU binaries reproducible without running pootc on every build.

One manifest lists every asset, its source and its destination. A test regenerates each asset and compares it byte for byte, and checks that each destination holds exactly its manifest's entries. `just regen-kernel-assets` regenerates them.

## Verification

Before codegen, `Body::verify` checks every matrix-fragment operation against its locals' `Ty::Fragment` type. Role (A, B or accumulator), operand dtype and tile shape must match at every producer and consumer, and a mismatch is a typed error with the statement location.

Matrix operations are collective over one 32-lane subgroup, so the verifier rejects one reachable under a branch that can split a subgroup (`DivergentFragmentParticipation`). Selecting a whole subgroup, such as warp 0, is accepted. The accumulator is an ordinary variable and carries across a K loop.

Executor tests dispatch the kernels on each device backend and compare against the CPU oracle ([Execution](./execution#verification)); PTX tests run on rented NVIDIA pods.
