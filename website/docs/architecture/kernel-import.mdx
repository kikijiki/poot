# Kernels from Rust

Imported GPU kernels are Rust functions, type-checked and borrow-checked by rustc. The same
source produces SPIR-V for wgpu, PTX for NVIDIA, and an AMDGCN code object for ROCm, not
separate implementations for each backend. (Other kernels are synthesized; see [Fusion](./fusion).)

## A kernel looks like this

```rust
#[kernel]
pub fn elementwise_add(a: &[f32], b: &[f32], out: &mut [f32]) {
    let i = thread_index();
    if i < out.len() {
        out[i] = a[i] + b[i];
    }
}
```

The `#[kernel]` attribute marks the function for import by pootc. The ABI is slices:
inputs as `&[T]`, outputs as `&mut [T]`. Thread index primitives (`thread_index`, `local_index`,
`group_index`, with `_x`/`_y`/`_z` variants) are intrinsics that lower to the correct hardware
registers on each target. The attribute renames the function into the reserved
`__poot_kernel_<name>` namespace for pootc; a normal host build gets a typed launch wrapper
instead of the body, so kernel bodies do not need to be host-compatible.

**pootc** is a thin rustc driver. It calls rustc normally (producing the normal compiled
artifact) and hooks `after_analysis` to visit every `#[kernel]` fn's MIR body using
Stable MIR [^stableMir], the stable, versioned interface to rustc's Mid-level IR
that does not change with every nightly.

**Kernel IR** (`poot-kernel-ir`) is a small CFG-based IR: basic blocks with statements
(`Assign`, `WorkgroupLocalWrite`, `VectorStore`, and the `Wmma*` matrix ops) and terminators
(`Goto`, `SwitchInt`, `ThreadIndexCall`, `Barrier`, `Return`, `Trap`). It
decouples the importer from the codegen backends, the importer only needs to know the
kernel IR; the backends only need to consume it. A bounds check that rustc inserts for a
slice index (`a[i]`) imports as a `Trap`: it aborts the dispatch on ROCm and PTX, and on
SpirvVulkan raises a typed fault at the next sync point (a failed check is never silently
dropped).

## How kernels connect to the graph executor

A kernel binary does not execute on its own; it is bound to a compute `Plan` produced by
`plan_eqn_analyzed`, which connects the import pipeline to the graph planning layer. `compile` runs
this planning as its last step.

There are two kinds of kernel body:

**Imported kernel**. References a `#[kernel]` fn that was compiled from Rust
source via pootc. The plan carries the imported kernel body, and the executor compiles and dispatches it for
the active backend.

Examples of ops handled by imported kernels:

- Decode `MatMul` -> `gemv_coalesced.rs`, `gemv_coalesced_bias.rs`, `gemv_batched_coalesced.rs`,
  `gemv_batched_coalesced_bias.rs` (plus BF16-weight variants)
- `FlashAttentionDecode` -> `flash_decode.rs`; `FlashAttentionPrefill` -> `flash_prefill.rs`
- `Gather` -> `gather_axis0.rs`, `gather_axis.rs`; `Scatter` -> `scatter_axis0.rs`
- Greedy and batched samplers -> `argmax_batched.rs`, `sample_*_gumbel_argmax_batched.rs`
- Packed projections -> `dense_bf16_contraction.rs`, `packed_bf16_row_gather.rs`,
  `packed_e4m3_row_gather.rs`

Sources live under `crates/pootc/kernels/<family>/` (one subdirectory per family: contraction,
attention, movement, packed, sampling, plus a `probe` family for kernels a backend crate loads
directly). Prefill GEMMs, the decode GEMV over a weight kept in checkpoint `[N, K]` orientation
(F32, F16 or BF16), and (single-sequence) flash attention are usually synthesized instead; see
[Fusion](./fusion).

**Synthesized kernel**. Generated by the fusion codegen from the op pattern. A
pointwise chain (Mul -> Exp -> Add -> ...) or a reduction-rooted region (Reduce(Max) -> Sub
-> Exp -> Reduce(Sum) -> Div) produces a unique kernel body on the fly. The synthesizer
generates kernel IR directly; poot-codegen lowers it to LLVM IR and then to SPIR-V, PTX, or an AMDGCN code object.

The key distinction: imported kernels are authored in Rust source; synthesized kernels are
generated from the op's shape. The optimizer and planner decide which to use for each eqn, by region
description and target, never by model. New work prefers growing a general lowering (elementwise,
reductions, contractions with fused epilogues, online softmax) over adding a kernel for one pattern.
There is no kernel DSL or parser.

## Accepted Rust subset

Anything outside this subset produces a named diagnostic from pootc, never a silent miscompile.

**Supported:**

| Construct                    | Notes                                                                                         |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| Integer and float arithmetic | `+`, `-`, `*`, `/`, `%`, bit ops, comparisons                                                 |
| Float intrinsics             | `sqrt`, `abs`, `floor`, `ceil`, `trunc`, `round`, `exp`, `ln`, `sin`, `cos`, plus `max`/`min` |
| Slice indexing               | `a[i]`, `a.len()`, bounds-guarded reads/writes; a failed bounds check traps the dispatch      |
| `for` loops                  | `for i in 0..n` and range variants                                                            |
| `while` loops                | scalar condition                                                                              |
| `if / else`                  | scalar boolean condition                                                                      |
| LDS read/write               | `wg_write(array, i, val)`, `wg_read(array, i)`: `array` is a literal workgroup-array id       |
| Workgroup barrier            | `workgroup_barrier()`                                                                         |
| Thread/group indexing        | `thread_index()`, `local_index()`, `group_index()` (and `_x`/`_y`/`_z`)                       |
| Global atomics               | `atomic_add`                                                                                  |
| Non-contracted add           | `no_contract_add(a, b)`: keep a mul-then-add unfused (no backend may contract it into an FMA) |
| Simple structs               | Field access, no methods with dynamic dispatch                                                |
| Helper fn inlining           | Small functions called from a kernel are inlined                                              |

**Not supported (rejected with diagnostic):**

| Construct                                 | Reason                                         |
| ----------------------------------------- | ---------------------------------------------- |
| Heap allocation (`Vec`, `Box`, `String`)  | No allocator on GPU                            |
| Dynamic dispatch (`dyn Trait`)            | No vtable on GPU                               |
| Private local arrays with dynamic indices | Crashes some SPIR-V drivers: use workgroup LDS |
| Closures (non-trivial)                    | Cannot be lowered through MIR import           |
| Recursive functions                       | No stack on GPU                                |
| Panics (`unwrap`, `expect`, `assert!`)    | Use `if i < a.len()` bounds guards instead     |
| Standard library I/O                      | No I/O on GPU                                  |

## LDS arrays and barriers

Workgroup-local (shared) memory is written and read with `wg_write` and `wg_read`, indexed by
a literal array id:

```rust
pub fn __poot_kernel_wg_reduce(a: &[f32], out: &mut [f32]) {
    let lane = local_index();
    wg_write(0, lane, a[lane]);   // array 0, slot `lane`
    workgroup_barrier();
    if lane == 0 {
        let mut acc = 0.0f32;
        for j in 0..64 { acc = acc + wg_read(0, j); }
        out[0] = acc;
    }
}
```

Use LDS instead of a local `[f32; N]` for SPIR-V: private arrays with dynamic indices
are miscompiled or crash some driver stacks (RADV on AMD). The imported flash decode kernel
keeps its running output `o[D]` in an LDS array for this reason. LDS works on wgpu, PTX and ROCm.

The structurization pass converts the kernel IR's unstructured CFG to structured control
flow (proper loops, if/else) before SPIR-V emit. This fixed a class of RADV driver
crashes on kernels with in-loop barriers.

## .kir.json assets and drift guarding

Each imported kernel has a committed `.kir.json` under its consuming crate's `assets/`
(`poot-graph-plan/assets/` for every kernel the planner chooses between; `poot-rocm-gpu/assets/` and
`poot-gpu/src/tests/assets/` for the handful a backend crate loads directly), generated from a source
under `crates/pootc/kernels/<family>/`. One manifest table lists every asset, its source and its
destination; a test regenerates each asset from its source and checks it byte-for-byte against the
committed one, and separately checks that each destination directory holds exactly its manifest's
entries. `just regen-kernel-assets` regenerates all of them.

Committing the kernel IR keeps GPU binaries reproducible from the repo without running pootc on every build.

## Verification

Before codegen, `Body::verify` checks known matrix-fragment producer roles: A, B and
accumulator. Conflicting producers and incompatible MMA or store operands return typed
errors with the offending statement location. Repeated accumulator updates remain valid.
These checks do not establish full fragment typing, subgroup participation or loop-carried
lowering; existing target and shape restrictions still apply.

`committed_assets_match_their_kernel_sources` regenerates every committed asset from its source and
fails if any is stale. Executor tests then dispatch each kernel on every backend and compare against
the CPU oracle under the contract described in [Execution](./execution#verification). PTX tests run on
rented NVIDIA pods.
