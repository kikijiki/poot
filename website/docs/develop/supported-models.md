# Supported models and formats

A model runs on a backend when compiling its graph for that backend succeeds. A refusal is a typed error that names the op or constant and the capability or limit the backend lacks.

The tables below are not written by hand. A test compiles three sets of graphs for every backend and writes the result between the markers:

- the fixture graphs of every registered model family
- the graphs of reference models at their real dimensions
- a dense model whose projections are stored in every weight format

The same region lists the library and server features the device lanes run, from the lanes' required-case lists.

Related pages:

- [Backends](../architecture/backends.mdx) describes the columns.
- [NPU offload](../architecture/npu.mdx) says what each NPU runs. The XDNA2 table is generated from what the planner says about each op.
- [Models](./models.md) says what a checkpoint must look like and how a family is added.
- [Serving capabilities](../serve/capabilities.md) lists serving features by backend.

## Reading the tables

### Statuses

- **Plans**: every graph of the row compiled for that backend. This says the planner can lower the graph. It does not say a real checkpoint of that family has run there.
- **Refused**: the cell shows the shape being compiled. The op or constant and the missing capability or limit are in the note under the table and in the badge's tooltip.
- **Rejected**: a compile failure that is not a missing capability, for example a graph over the compile limits.
- **Required** and **No case**: these come from the required-case lists of the device lanes, not from the planner. **Required** carries the number of cases that exercise the feature on that backend. **No case** is a gap in the lane, not a refusal.

### Rows

- A fixture row is the family's graphs at a few dozen channels.
- A Real dimensions row is the graphs a real checkpoint traces, over zero weights. A limit that only a real width reaches shows there.
- A row is a family key, or `family/variant` for one of the family's option fixtures. A Mixtral or Granite MoE checkpoint is the llama or granite family with experts.
- A weight over a backend's single-buffer limit still plans when the planner splits it into row chunks. Qwen3.8-27B's 2.5 GB embedding table on wgpu is one.
- The Refusals table gives every backend one refusal: a real model against a device limit it exceeds.
- Mixtral-8x22B is that refusal. Its stacked expert table is larger than the wgpu preset's single-buffer limit.
- wgpu and raw Vulkan share that RADV limit, so both refuse it on their own caps. ROCm and PTX plan it and refuse it only when given that limit.

### Formats

- The weight-format table binds a random admitted payload of each format as the stored bytes. It checks the lowering, not the numbers.
- A GGUF Mixtral names the `llama` architecture. It loads as the llama family with experts when its metadata has `llama.expert_count`. A DeepSeek-V3 GGUF names `deepseek2`.
- MXFP4 weights stay packed at load time. The routed-expert projection is one indexed packed contraction that reads only the selected experts' blocks.
- Dense BF16 and F16 weights are kept as stored words, with no host f32 copy. Packed checkpoint size is not a bound on total peak memory.
- Per-channel E4M3 `compressed-tensors` projections load packed and use the shared generated lowering. See [Using quantized checkpoints](../serve/quantized-checkpoints.md).

### Verified on real checkpoints

- Qwen3.8-27B-FP8 generates "Paris" for "The capital of France is" on PTX (one H100 80 GB). The first token's top-five log-probabilities equal the CPU oracle's within 1e-3.
- It generates coherent text on ROCm (gfx1151), where the top-five comparison has not been run. It has not run on wgpu.
- Qwen3.8-Flash-Next has synthetic fixtures that match an independent f64 reference. Its real Q2 GGUF runs on PTX on one 96 GB card and on ROCm (gfx1151, 128 GB unified memory) at about 19 tokens/s decode. wgpu and Vulkan refuse it at plan time: its 26.8 GiB per-layer embedding table is a packed source beyond what the SPIR-V kernels address.
- For a short prompt its logits match llama.cpp's on the same file within the comparison limits: mean KL 0.018 against a limit of 0.064. The greedy text is coherent. A long prompt window has no verified receipt yet.
- DeepSeek-V4, MiniMax-M2 and GLM-5.3-Flash have synthetic fixtures that match an independent f64 reference. No real public checkpoint of them has run.
- The `bert` family runs on the driver's `encode` step (`poot_llm::encoders`). `poot-serve` runs `encode` steps for a decoder's embeddings and reranking on wgpu and ROCm.
- `poot-serve` also starts on a BERT checkpoint, for embeddings and cross-encoder rerank. The encode shapes are fitted and prepared before it serves.

## Load limitations by family

The tables above say which graphs plan. These are the checkpoints and configs a family's loader refuses. Each refusal is a typed error naming the field, tensor or type.

### DeepSeek-V4

- Only a Hugging Face checkpoint loads. A GGUF is refused as unsupported.
- A real quantized checkpoint is refused at load. Its E4M3 projections carry `.scale` siblings, and no loader builds the packed layout from them. The packed layouts exist only in the family's test fixtures.
- An `F8_E4M3` weight without a `.weight_scale` or `.weight_scale_inv` sibling is a layout error. It is never read as unscaled dense weights.
- A `rope_scaling` entry other than plain rotary is refused.
- A `scoring_func` other than `sqrtsoftplus` is refused.
- Equal compression rates for the two compressed attention kinds are refused.
- A `compress_ratios` entry that is neither `0` nor one of the two rates is refused.

### GLM-5.3-Flash

- Only a Hugging Face checkpoint loads. A GGUF is refused as unsupported.
- These config values are refused: a `hidden_act` other than `silu`, a `scoring_func` other than `sigmoid`, a `topk_method` other than `noaux_tc`, and attention bias.
- The `mla_use_nope`, `index_kpool_compress` and `index_kpool_always_select_tail` flags are refused when explicitly set the other way. An absent key takes the supported value.
- A layer is a `linear_attention` or `deepseek_sparse_attention` mixer with a `dense` or `sparse` feed-forward. Any other `layer_types` or `mlp_layer_types` entry is refused.
- A sparse-attention layer with a nonzero `qk_rope_head_dim` is refused, and so is any `indexer_types` entry other than `full`.

### Phi-3

- A Hugging Face `longrope` block (Phi-3.5-mini, Phi-4-mini) is read into the RoPE tables. The short factors apply while the step capacity is within `original_max_position_embeddings`. Past it, the long factors and the attention scale apply, as llama.cpp picks them.
- A GGUF that carries `rope_factors_long.weight` or `rope_factors_short.weight` is refused, naming the tensor.
- A `longrope` block is refused when it has an `attention_factor`, or a factor table whose length is not half the rotary width.

### Any GGUF

A quantized tensor whose ggml type has no packed format is refused at load, by tensor name and type. It is never loaded as dense weights silently.

- Refused types: Q8_1, Q8_K, IQ2_XXS, IQ2_S, IQ1_S, IQ1_M, TQ1_0 and TQ2_0.
- This holds for Qwen3.8-Flash-Next and every other GGUF family.
